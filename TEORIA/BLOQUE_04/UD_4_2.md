# UD02 — Herencia en la Programación Orientada a Objetos (POO) en Python

## 0. Objetivos de la unidad

Al finalizar esta unidad deberías ser capaz de:

- Explicar qué es la herencia y cuándo tiene sentido usarla.
- Crear clases base y subclases en Python.
- Sobrescribir métodos en clases hijas.
- Usar `super()` correctamente.
- Diferenciar herencia de composición.
- Reconocer problemas comunes derivados de un mal uso de la herencia.

---

## 1. Concepto de herencia

La **herencia** permite crear nuevas clases (**subclases**) a partir de clases existentes (**superclases**), reutilizando y extendiendo su comportamiento.

La herencia modela una relación **“es-un”**:

- Un `Dog` **es un** `Animal`
- Un `Manager` **es un** `Employee`

Si la relación es **“tiene-un”**, suele ser mejor usar **composición**.

---

## 2. Herencia simple: sintaxis básica

En Python, una clase hereda de otra indicando la clase base entre paréntesis:

```python
class Animal:
    def speak(self) -> str:
        return "..."

class Dog(Animal):
    def speak(self) -> str:
        return "Woof"
````

Uso:

```python
animal = Animal()
dog = Dog()

print(animal.speak())  # ...
print(dog.speak())     # Woof
```

Claves:

* `Dog` hereda de `Animal`.
* `Dog` puede usar métodos definidos en `Animal`.
* `Dog` puede **sobrescribir** métodos de la clase base.

---

## 3. Constructores y `super()`

Si la clase base define `__init__`, la subclase debe llamar a dicho constructor para inicializar correctamente el objeto.

```python
class Employee:
    def __init__(self, name: str, salary: float) -> None:
        self.name = name
        self.salary = salary

class Manager(Employee):
    def __init__(self, name: str, salary: float, team_size: int) -> None:
        super().__init__(name, salary)
        self.team_size = team_size
```

Claves:

* `super()` devuelve un proxy a la clase base.
* Evita duplicar código del constructor padre.
* Mejora mantenibilidad y legibilidad.

---

## 4. Sobrescritura (override) de métodos

Una subclase puede redefinir un método de la clase base para cambiar o especializar su comportamiento.

```python
class Vehicle:
    def start(self) -> str:
        return "Vehicle starting"

class Car(Vehicle):
    def start(self) -> str:
        return "Car engine starting"
```

El método ejecutado depende del **tipo real del objeto**, no del tipo de la variable.

---

## 5. Extensión del comportamiento con `super()`

A veces interesa **ampliar** el comportamiento del método base, no sustituirlo completamente.

```python
class Logger:
    def log(self, message: str) -> str:
        return f"[INFO] {message}"

class FileLogger(Logger):
    def log(self, message: str) -> str:
        base_message = super().log(message)
        return f"{base_message} -> written to file"
```

---

## 6. Herencia y visibilidad (convenciones)

Las subclases **pueden acceder** a atributos “protegidos” por convención (`_attr`).

```python
class Account:
    def __init__(self, balance: float) -> None:
        self._balance = balance

class SavingsAccount(Account):
    def add_interest(self, rate: float) -> None:
        self._balance += self._balance * rate
```

No se recomienda acceder directamente a atributos con `__name` (*name mangling*).

---

## 7. Herencia múltiple (nociones básicas)

Python permite herencia múltiple, pero introduce complejidad:

```python
class Flyable:
    def fly(self) -> str:
        return "Flying"

class Swimmable:
    def swim(self) -> str:
        return "Swimming"

class Duck(Flyable, Swimmable):
    pass
```

⚠️ Recomendación:

* Usar herencia múltiple solo con **mixins pequeños y bien definidos**.
* Evitar jerarquías complejas.

---

## 8. Herencia vs composición

### 8.1. Ejemplo incorrecto de herencia

```python
class Engine:
    def start(self) -> str:
        return "Engine started"

class Car(Engine):  # ❌ Car no es un Engine
    pass
```

### 8.2. Ejemplo correcto con composición

```python
class Engine:
    def start(self) -> str:
        return "Engine started"

class Car:
    def __init__(self, engine: Engine) -> None:
        self.engine = engine

    def start(self) -> str:
        return self.engine.start()
```

---

## 9. Problemas comunes con herencia

* Jerarquías demasiado profundas.
* Clases base demasiado genéricas.
* Subclases que no cumplen el contrato lógico de la base.
* Uso excesivo de `isinstance`.

Un síntoma habitual de mal diseño es tener muchos `if/elif` para distinguir tipos.

## 11. Mini-resumen

* La herencia modela relaciones **“es-un”**.
* Permite reutilizar y especializar comportamiento.
* `super()` es clave para constructores y métodos extendidos.
* La herencia múltiple existe, pero debe usarse con cuidado.
* Ante la duda, **composición antes que herencia**.
