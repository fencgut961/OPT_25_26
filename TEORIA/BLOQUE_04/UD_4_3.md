## 1. Concepto de polimorfismo

El **polimorfismo** permite tratar objetos de **distintas clases** de forma uniforme, siempre que compartan un **comportamiento común**.

Idea clave:
> *Mismo mensaje, diferentes comportamientos.*

En Python, el polimorfismo es natural gracias a:
- la herencia
- el *duck typing* (tipado dinámico)

---

## 2. Polimorfismo por subtipado (herencia)

Cuando varias subclases sobrescriben un mismo método, pueden usarse indistintamente a través de la clase base.

```python
class Shape:
    def area(self) -> float:
        raise NotImplementedError
````

```python
class Rectangle(Shape):
    def __init__(self, width: float, height: float) -> None:
        self.width = width
        self.height = height

    def area(self) -> float:
        return self.width * self.height
```

```python
class Circle(Shape):
    def __init__(self, radius: float) -> None:
        self.radius = radius

    def area(self) -> float:
        return 3.14159 * self.radius * self.radius
```

Uso polimórfico:

```python
def total_area(shapes: list[Shape]) -> float:
    return sum(shape.area() for shape in shapes)
```

El código **no necesita saber** si es un `Rectangle` o un `Circle`.

---

## 3. Polimorfismo y enlace dinámico

El método que se ejecuta se decide **en tiempo de ejecución**, según el tipo real del objeto.

```python
shape: Shape = Circle(10)
print(shape.area())  # Ejecuta Circle.area
```

Esto se denomina **enlace dinámico**.

## 4. Duck typing

En Python no es necesario heredar de una clase base.
Basta con que el objeto tenga el método esperado.

> “If it walks like a duck and quacks like a duck, it is a duck.”

```python
class CsvExporter:
    def export(self, data: list[dict]) -> str:
        return "csv data"

class JsonExporter:
    def export(self, data: list[dict]) -> str:
        return "json data"
```

Función polimórfica:

```python
def run_export(exporter, data: list[dict]) -> str:
    return exporter.export(data)
```

No importa la clase concreta, solo el **comportamiento**.

---

## 5. Polimorfismo sin herencia (diseño estructural)

Ventajas:

* Menos acoplamiento.
* Mayor flexibilidad.
* Facilita pruebas y extensiones.

Ejemplo típico: estrategias.

```python
class FixedDiscount:
    def calculate(self, price: float) -> float:
        return price - 10

class PercentageDiscount:
    def calculate(self, price: float) -> float:
        return price * 0.9
```

```python
def apply_discount(strategy, price: float) -> float:
    return strategy.calculate(price)
```

## 6. Clases abstractas (ABC)

Las **Abstract Base Classes** permiten definir una interfaz explícita y forzar su implementación.

```python
from abc import ABC, abstractmethod

class PaymentMethod(ABC):
    @abstractmethod
    def pay(self, amount: float) -> str:
        pass
```

```python
class CardPayment(PaymentMethod):
    def pay(self, amount: float) -> str:
        return f"Paid {amount} by card"
```

Ventajas:

* Contratos claros.
* Errores detectados antes.
* Diseño más explícito.

---

## 7. Protocols (tipado estructural)

Los **Protocols** permiten expresar *duck typing* con anotaciones de tipo.

```python
from typing import Protocol

class Exporter(Protocol):
    def export(self, data: list[dict]) -> str:
        ...
```

```python
def run_export(exporter: Exporter, data: list[dict]) -> str:
    return exporter.export(data)
```

Ventaja:

* Sin herencia.
* Compatible con comprobadores de tipos (mypy, pyright).

---

## 8. Errores comunes

❌ Uso excesivo de `if/elif` por tipo:

```python
def process(shape):
    if isinstance(shape, Rectangle):
        ...
    elif isinstance(shape, Circle):
        ...
```

✔️ Enfoque polimórfico correcto:

```python
def process(shape):
    return shape.area()
```

## 9. Beneficios del polimorfismo

* Código más limpio y extensible.
* Menor acoplamiento.
* Facilita mantenimiento y pruebas.
* Permite añadir nuevas clases sin modificar código existente
  (*Open/Closed Principle*).

## 11. Mini-resumen

* Polimorfismo = mismo mensaje, distintos comportamientos.
* Puede lograrse con herencia o sin ella (*duck typing*).
* Python favorece el diseño estructural.
* ABC y Protocols ayudan a definir contratos.
* Evitar condicionales basados en tipos.
