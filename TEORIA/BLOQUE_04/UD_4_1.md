## 1. ¿Qué es la POO?

La **Programación Orientada a Objetos** es un paradigma en el que modelamos el software como un conjunto de **objetos** que combinan:

- **Estado**: datos del objeto (atributos)
- **Comportamiento**: acciones del objeto (métodos)

Python soporta POO de forma nativa y, de hecho, “casi todo” en Python es un objeto.

---

## 2. Clases y objetos

- **Clase**: define un “tipo” (plantilla).
- **Objeto (instancia)**: una creación concreta basada en esa clase.

Ejemplo mental:
- Clase: `Student`
- Objeto: `Student("Ana", 20)`

---

## 3. Primer ejemplo: clase, constructor y método

```python
class Student:
    def __init__(self, name: str, age: int) -> None:
        self.name = name
        self.age = age

    def birthday(self) -> None:
        self.age += 1


student = Student("Ana", 20)
student.birthday()
print(student.name, student.age)  # Ana 21
````

Claves:

* `self` es la referencia al propio objeto.
* `__init__` se ejecuta al crear la instancia.
* `self.name` y `self.age` son **atributos de instancia**.

## 4. Atributos de instancia vs atributos de clase

### 4.1. Atributos de instancia

Pertenecen a cada objeto.

```python
class Student:
    def __init__(self, name: str) -> None:
        self.name = name
```

### 4.2. Atributos de clase

Pertenecen a la clase y se comparten entre instancias.

```python
class Student:
    school_name = "IES Example"

    def __init__(self, name: str) -> None:
        self.name = name


s1 = Student("Ana")
s2 = Student("Luis")

print(s1.school_name)  # IES Example
print(s2.school_name)  # IES Example
```

## 5. Métodos y responsabilidades

Un buen diseño suele:

* mantener métodos con una responsabilidad clara
* evitar métodos “cajón desastre”
* evitar exponer estado innecesariamente

Ejemplo: encapsular comportamiento en métodos:

```python
class BankAccount:
    def __init__(self, owner: str, balance: float = 0.0) -> None:
        self.owner = owner
        self._balance = balance

    def deposit(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("Amount must be positive")
        self._balance += amount

    def withdraw(self, amount: float) -> None:
        if amount <= 0:
            raise ValueError("Amount must be positive")
        if amount > self._balance:
            raise ValueError("Insufficient funds")
        self._balance -= amount
```

## 6. Encapsulación en Python

Python no aplica “private/protected” como Java, pero sí hay **convenciones**:

* `public_attr` → público
* `_internal_attr` → “uso interno / protegido” por convención
* `__name` → *name mangling* (evitar colisiones, no “seguridad” real)

### 6.1. Propiedades con `@property`

Permite exponer lectura/escritura con control y validación.

```python
class Person:
    def __init__(self, name: str) -> None:
        self._name = name

    @property
    def name(self) -> str:
        return self._name

    @name.setter
    def name(self, value: str) -> None:
        if not value.strip():
            raise ValueError("Name cannot be empty")
        self._name = value
```

Uso:

```python
p = Person("Ana")
p.name = "Luis"
print(p.name)
```

## 7. `__repr__` y `__str__`

Ayudan a depurar y a imprimir objetos de forma útil.

* `__repr__`: orientado a depuración (idealmente “representación inequívoca”)
* `__str__`: orientado a usuario

```python
class Product:
    def __init__(self, name: str, price: float) -> None:
        self.name = name
        self.price = price

    def __repr__(self) -> str:
        return f"Product(name={self.name!r}, price={self.price})"

    def __str__(self) -> str:
        return f"{self.name} ({self.price:.2f}€)"
```

## 8. Métodos de instancia, de clase y estáticos

### 8.1. Método de instancia

Recibe `self` y trabaja con el estado de la instancia.

```python
class Counter:
    def __init__(self) -> None:
        self.value = 0

    def increment(self) -> None:
        self.value += 1
```

### 8.2. Método de clase (`@classmethod`)

Recibe `cls`. Útil para constructores alternativos o configuración.

```python
class Temperature:
    def __init__(self, celsius: float) -> None:
        self.celsius = celsius

    @classmethod
    def from_fahrenheit(cls, f: float) -> "Temperature":
        c = (f - 32) * 5 / 9
        return cls(c)
```

### 8.3. Método estático (`@staticmethod`)

No recibe `self` ni `cls`. Es una función “relacionada” con la clase.

```python
class MathTools:
    @staticmethod
    def is_even(n: int) -> bool:
        return n % 2 == 0
```

## 9. Composición vs herencia (adelanto)

Antes de heredar, pregúntate:

* ¿La relación es **“es-un”**? → herencia puede tener sentido.
* ¿La relación es **“tiene-un”**? → normalmente **composición**.

Ejemplo “tiene-un”:

```python
class Engine:
    def start(self) -> str:
        return "Engine started"

class Car:
    def __init__(self, engine: Engine) -> None:
        self.engine = engine

    def start(self) -> str:
        return self.engine.start()
```

## 11. Mini-resumen

* Una **clase** define un tipo; un **objeto** es una instancia.
* Los **atributos** guardan estado; los **métodos** definen comportamiento.
* Encapsulación en Python: convención con `_` y validación con `@property`.
* `__repr__`/`__str__` mejoran depuración e impresión.
* Métodos: instancia (`self`), clase (`cls`), estático (sin `self/cls`).
